# 낙서 이어달리기 설계

작성일: 2026-10-21 · 대상: suu3/ddangkong의 main · 상태: 사용자 검토용

## 목적과 확정 방향

친구들이 각자 모바일 웹으로 접속해서 문장과 그림을 번갈아 전달하고, 마지막에 변화를 함께 보는 무료 파티게임을 추가한다. 사용자는 기존 모바일 웹과 스타일을 유지하고 main에서 작업하도록 요청했다. 이름은 가칭 ‘낙서 이어달리기’, 경로는 /drawing-relay, 게임 식별자는 drawing_relay로 한다. 전통적인 그림 전화놀이 규칙을 사용하며 다른 게임의 이름, UI, 이미지, 문구, 코드는 복제하지 않는다. 제공된 기획안의 외부 이미지도 사용하지 않는다.

## 기술 선택

권장안은 기존 Next.js 화면, 공통 방 세션/연결, Cloudflare Worker와 SQLite Durable Objects를 확장하는 것이다. 기존 게임용 공개 상태와 새 게임의 비공개 저장 상태를 분리한다. Socket.IO 서버를 별도로 만드는 대안은 배포와 운영 대상을 늘린다. 한 기기를 돌려쓰는 대안은 각자 폰으로 동시 참여한다는 목표에 맞지 않는다.

## 화면과 스타일

홈의 파티게임 영역에 기존 GameMenu 카드와 배지를 사용해 추가한다. chocolate 색 토큰, UniqueText, MainButton, 기존 둥근 카드와 여백을 사용한다. 독자 제작한 단순 SVG 연필/종이 아이콘을 사용한다. 기존 햄버거와 소리 설정은 공통 Navigation을 통해 유지한다.

소개 → 닉네임/방 생성·링크 참가 → 대기실 → 문장/그림 작성 → 제출 후 대기 → 결과 공개 흐름이다. 기존 방 공유 UI를 재사용하고 새 서버나 짧은 초대코드 시스템은 추가하지 않는다. 대기실은 참가자, 방장, 준비 상태, 4~10명 안내, 링크 공유, 게임 시작을 표시한다. 문장은 100자까지 입력한다. 각 차례에 남은 시간과 제출 인원만 보여준다.

375px 화면에서 가로 넘침이 없어야 한다. 그림판은 화면 폭에 맞는 정사각형이며 정규화한 좌표를 사용한다. Pointer Events와 포인터 캡처로 터치/마우스를 처리하고, 그림 영역에만 touch-action: none을 적용한다. 색 선택과 도구 버튼은 최소 44px 터치 영역과 접근성 이름/선택 상태를 제공한다. 펜, 지우개, 6색, 되돌리기를 제공한다. 캔버스 밖에서는 스크롤이 가능하다.

## 진행 규칙

방장을 포함해 4~10명이 준비하면 방장만 시작할 수 있다. 시작 시 참가자 순서를 고정한다. 참가자 N명은 N개의 체인에 각각 한 번씩 기여하며 총 N단계를 진행한다. 0단계는 최초 문장이고, 짝수 단계는 문장 30초, 홀수 단계는 그림 60초다. 체인 c의 단계 r 담당자는 참가자 (c+r) mod N이다. 각 담당자는 해당 체인의 직전 단계 하나만 본다. 모두 제출하면 즉시 다음 단계로 이동한다. N이 짝수라 마지막이 그림이어도 그대로 공개한다.

제출한 내용은 수정할 수 없다. 현재 게임/단계 ID와 명령 ID로 중복 제출을 무해하게 처리하고 오래된 단계 제출을 거절한다. 클라이언트 전체 revision 충돌만으로 동시 제출을 잃지 않게 서버에서 명령을 직렬 처리한다. 서버 시각으로 마감을 확정하고 클라이언트에는 서버 시각과 마감 시각을 함께 보낸다.

## 그림과 초안

그림은 실행 가능한 SVG/HTML이나 외부 이미지 URL 대신 검증된 선 데이터로 저장한다. 좌표 0~1, 허용 색/도구, 선 굵기 범위를 검증한다. 그림당 최대 120개 선·총 2,000개 점·직렬화 48KiB로 제한해 기존 메시지 64KiB 한도를 넘기지 않는다. 입력 시 점 단순화/샘플링을 적용하고 한도 도달 시 안내한다. 단일 점도 찍히며 지우개는 흰 배경 위에 그리는 선으로 표현한다. 저장 시 같은 선 데이터를 Canvas에 재생한다.

작성 중 로컬 초안을 방/게임/단계/참가자별로 보관하고, 변경 후 최대 1초 간격으로 서버에 최신 초안을 저장한다. 연결된 상태에서 마감 시 현재 내용을 제출하고, 서버 alarm은 미제출자의 마지막 저장 초안으로 확정한다. 연결이 끊겼다면 서버에 도착하지 않은 변경은 복구를 보장하지 않는다. 빈 문장은 ‘전달된 문장이 없어요’, 빈 그림은 빈 종이 안내로 표현한다. 자동 확정 여부를 결과에 표시한다.

## 서버 상태와 공개 범위

서버 전용 상태는 참가자 고정 순서, 전체 체인/제출물, 비공개 초안, 현재 단계, 마감, 게임 ID, 공개 위치를 저장한다. 클라이언트 상태는 공개 방 정보와 참가자/제출 여부, 현재 단계/마감, 본인의 초안/제출 상태, 본인에게 배정된 직전 제출물만 포함한다. 방장도 다른 사람의 비공개 기록을 받지 않는다.

공개 HTTP 방 조회는 새 게임의 진행 단계/기본 정보만 반환한다. 인증된 HTTP 응답, WebSocket 최초 snapshot, state_updated, 오류의 room 필드, 재접속 응답 등 모든 경로가 동일한 참가자별 projection을 통과해야 한다. 서버 내부 상태를 공통 publicRoom이나 전체 broadcast에 직접 넣지 않는다. 초안 저장은 다른 참가자에게 내용이나 불필요한 이벤트를 전파하지 않는다. 기존 네 게임의 응답 형식은 유지한다.

참가/준비/본인 초안 저장/본인 제출 명령을 추가하고, 시작/공개 진행/다시하기는 방장만 허용한다. actor ID 입력만 신뢰하지 않고 기존 세션 인증으로 식별한다. 새 게임은 임의의 state_update를 거절한다. 제출물의 종류·담당자·게임 ID·단계·마감·크기까지 서버에서 검사한다. 진행 중인 방에 새 참가자는 합류할 수 없고, 기존 참가자의 인증된 재접속만 허용한다.

## 타이머, 연결 종료와 결과

Durable Object alarm이 다음 마감과 방 만료를 예약한다. 마감 처리와 마지막 제출이 동시에 들어와도 단계는 한 번만 전환한다. 모든 상태를 먼저 저장하고 그 후 각 세션에 필요한 응답을 보낸다. 서버 재개 시 지난 마감을 정리하되, 새로 시작한 다음 단계에는 온전한 제한시간을 부여한다.

진행 중 퇴장해도 고정 순서를 유지하며 해당 참가자의 미제출은 마감 때 초안/빈 제출로 채운다. 동일 세션 재접속은 현재 단계와 본인 초안을 복원한다. 방장 연결이 끊겨도 작성 단계는 자동 진행한다. 공개 제어와 다시하기는 기존 방장이 재접속하면 이어서 가능하고, 방장 자동 승계는 이번 범위에서 제외한다. 연결 중·끊김·재시도·만료 상태를 명시한다.

N단계 후 결과 모드로 이동한다. 방장이 체인 순서대로 한 장씩 공개하며 전원에게 공개 위치를 동기화한다. 서버는 공개된 부분만 전송하므로 미공개 기록은 네트워크 응답에도 없다. 모든 체인을 공개하면 각 체인의 전체 흐름을 Canvas로 합성해 PNG로 저장할 수 있다. 브라우저 공유/다운로드를 지원하고 저장이 어려운 모바일에서는 이미지 보기 안내를 제공한다. 점수·우승은 없다. 다시하기는 방장이 실행하고 기존 연결을 유지한 채 체인/초안/준비 상태와 게임 ID를 초기화한다. 방 만료는 기존 24시간 정책을 따른다.

## 코드 구성

app/drawing-relay/page.tsx는 src/views/drawing-relay의 페이지를 연결하고 useSearchParams에는 Suspense 경계를 둔다. 화면 로직은 model, 화면/그림판은 ui로 나눈다. 게임 규칙과 데이터 검증은 순수 함수로 분리하고 브라우저 Canvas에 의존하지 않는다. entities/room과 shared/api에는 새 게임 타입, 인증된 명령과 참가자별 snapshot 지원을 추가한다. workers/realtime에는 별도 게임 규칙 및 projection 모듈을 두고 기존 라우팅·인증·alarm과 연결한다. views → widgets → entities → shared 의존 방향을 지킨다.

## 검증과 배포 조건

순수 규칙 테스트로 4·5·10명 배정, 중복 기여 방지, 짝수/홀수 종료, 자동 제출과 단 한 번의 단계 전환을 검증한다. Worker 테스트는 최소 인원, 권한, 세션 위장, 진행 중 참가, 중복/과거 제출, 크기 제한, 전체 HTTP/WS/오류/재접속의 미공개 기록 누출을 확인한다. 초안 격리와 공개 위치 이후 기록의 비노출도 검사한다.

독립 브라우저 4개로 시작부터 제출·결과·다시하기까지 확인한다. 서버 alarm, 새로고침, 끊김/재접속, 동시 제출과 375px 터치 그리기·스크롤을 검증한다. 기존 네 게임 회귀 확인을 포함한다. pnpm test, test:worker, test:e2e, lint, build 및 Worker TypeScript 검사를 수행한다. 웹과 Worker 양쪽에 변경이 필요하며 Worker를 먼저 반영한 후 웹을 반영한다. 배포 자격증명이나 배포 권한이 준비되지 않으면 구현 완료와 배포 완료를 구분해 보고한다.

## 제외 범위와 검토 상태

회원가입, 공개 방 검색, 채팅, AI, 경쟁 점수, 특수 모드, 별도 서버, 영구 갤러리는 추가하지 않는다. 이름·코드·에셋 독자 제작은 권리 침해 부재를 보장한다는 뜻이 아니다.

자체 검토: 원안의 PC 우선을 모바일 우선으로 수정했고, 신규 Socket.IO 대신 기존 Worker를 선택했다. 미공개 자료 보호, 동시 제출, 초안과 타임아웃, 퇴장, 방장 부재, 메시지 크기, 결과 저장 정책을 구체화했다. 제품 코드는 아직 변경하지 않았다. Git 복제는 환경의 프록시 연결 실패로 불가능하여 이 문서는 로컬 검토 파일이며 저장소에 커밋하지 않았다.
