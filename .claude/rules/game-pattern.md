# V3 게임 개발 기준

- 라우트 파일은 views의 페이지를 연결한다. 화면별 상태 선택·계산은 model/use*View 훅, 렌더링은 ui에서 담당한다.
- 로컬 게임 상태는 기존 reducer/Context를 사용한다. 실시간 공통 상태는 entities/room의 useRoom과 store가 소유한다.
- WebSocket을 화면·공유 패널마다 만들지 않는다. 동일 방은 공통 연결 하나를 공유하고 마지막 구독 해제 때 닫는다.
- 조작은 store의 직렬 큐에서 최신 상태로 계산한다. 서버가 승인·저장한 상태만 전파한다. 저장 전 무권한 broadcast를 만들지 않는다.
- 진행자만 전체 상태 변경. 참가자는 본인의 선택/별명/준비/폭탄 전달 명령만 보낸다. 공개 actor ID만으로 권한을 판단하지 않는다.
- 커피 카드 번호는 기존 useDeck처럼 1부터 total까지다. 선택은 서버 상태에 저장해 새로고침 후 복원한다.
- 폭탄 전달 대상은 현재 연결된 참가자에서 고른다. 현재 보유자만 전달할 수 있다. 서버 alarm으로 시간 종료를 확정한다.
- 연결 중·재연결·오류·만료를 UI에 표시한다. 방 변경/해제 시 이전 비동기 응답과 타이머가 새 방을 오염시키지 않게 한다.
- TanStack Query나 Suspense 데이터 로딩을 의무적으로 도입하지 않는다.

검증은 두 브라우저의 결과 일치, 참가자 권한 제한, 새로고침과 재접속, 동시 조작, 375px 가로 오버플로를 확인한다. 반복 테스트는 실행별 임시 Worker 저장소로 생성 제한과 격리한다.
